# Milestone 3 — Real-Document Validation and Robustness

Engineering robustness validation of the Milestone 2 pipeline against a realistic
local document corpus. **This is not a statistically valid benchmark**: the corpus
is small (15 documents), synthetic-but-realistic, and written in TRA-style
vocabulary. No scientific accuracy claim is made or implied.

Frozen during this milestone: Milestone 1 (unchanged), Milestone 2 architecture
(unchanged — one config value fixed under TDD, see §13), no commits, no API/frontend.

## 0. Pre-M3 validation coverage (Stage 1 inventory)

Previously covered by tests: inline 10-sentence synthetic text; tiny `.txt`/`.md`
files; 1–2 page generated PDFs; malformed bytes; sentence/cue/match unit fixtures;
synthetic aggregation/gap fixtures. **Not covered:** documents >10 sentences or
>2 pages; multi-page headers/footers end-to-end; ambiguous adjacent-TRL evidence;
contradictory documents end-to-end; irrelevant/boilerplate-heavy documents;
TRL-number keyword leakage; negated/speculative/repeated claims; T6–T9 criteria
e2e; traceability assertions; golden envelopes; CLI failure handling; performance;
cross-run determinism for PDFs. Milestone 3 addresses all of these.

## 2. Expected assessment envelopes

`data/validation/envelopes.json` — 15 cases, **pre-registered before the first
run**, each derived from the document's own evidence against
`configs/trl_criteria_v1.json`. Per case: expected status, expected TRL (or
acceptable range for genuine adjacent ambiguity), minimum confidence band,
required supported criteria, expected unsatisfied next-level (blocker-gap)
criteria, abstention flag, contradiction flag. Where evidence genuinely spans
adjacent levels (`05_ambiguous_adjacent`), the envelope allows range `[4, 5]`
while pinning the policy-v1 output (`4`).

## 4. False positives

**None observed.** No document was assessed at a level its evidence does not
support: no inflated maturity from noise (`07`), roadmap talk (`adv_leakage`),
TRL numbers (`pair_c`, `adv_leakage`), repetition (`adv_negated`), or
other-technology mentions (`adv_negated`).

## 5. False negatives

**One found and fixed (Stage 9):** `07_irrelevant_technical` initially abstained
(`insufficient_evidence`, T1.C1 missing) because its genuine T1 evidence sat as
the 21st sentence of a long Prior Art section and was discarded by
`max_candidates_per_section: 20` (cap applied before cue filtering).
RED regression test reproduced it; GREEN fix raised the resource-guard cap to
200. Post-fix: assessed at TRL 2 as the evidence requires. No other false
negative against the pre-registered envelopes (14/15 passed on first run).

## 6. Abstention behavior

Four cases abstain (`predicted_trl: null`, never a guessed level):
- `08_insufficient` — zero evidence (0 items)
- `10_scanned_image_only` — no extractable text (loader warnings
  `no_extractable_text`, `possibly_scanned_image_only`; status
  `insufficient_evidence`, not `failed`)
- `adv_leakage` — TRL-number claims with zero supporting evidence
- pre-fix `07` — false-negative abstention, eliminated by the §5 fix

All abstentions exit the CLI with code 0 and a well-formed payload.

## 7. Adjacent-level discrimination

- `pair_a_lab` (relevant-env testing only *planned*) → **TRL 4**
- `pair_b_relevant_env` (identical text; planned sentence replaced by an actual
  relevant-environment component test + fidelity justification) → **TRL 5**;
  gained criteria exactly `{T5.C1, T5.C2}`
- Text diff confirms the pair differs only in that one maturity condition, and
  neither pair file contains a `TRL <number>` string
- `05_ambiguous_adjacent` → policy output 4 with T5.C1 satisfied and T5.C2 only
  prospective — envelope documents genuine adjacency range `[4, 5]`

## 8. Leakage / adversarial results

- `adv_leakage` ("TRL 9", "expected to reach TRL 8", "future TRL 7 target",
  "previously achieved TRL 5") → **abstains**; the single extracted roadmap item
  is `insufficient`, never `supports`; `supported_criteria == []`
- `pair_c_talk` (adds "The program is now at TRL 6 following successful testing
  of the prototype.") → result identical to `pair_a` on status, TRL, confidence,
  supported/missing criteria, and gaps — explicit TRL keywords match no
  criterion hint and cannot drive maturity
- `adv_negated`: negated relevant-environment claim surfaces in
  `contradictory_evidence`; speculative flight claim stays non-supporting;
  two verbatim repetitions keep unique evidence IDs and do not move the level
  (stays 2); lidar/other-tech sentence captured as no evidence

## 9. Traceability verification

For **all 132 evidence items across all 15 documents**, automated tests assert:

1. every supported criterion carries ≥1 backing evidence ID (also in
   `gap_analysis.demonstrated`)
2. every evidence ID recomputes exactly from
   `(document_id, page, block_id, start_char, criterion_id)`
3. `block.text[start_char:end_char] == quote` (quote-clipping handled) — the
   quote resolves to a real source span
4. PDF page numbers: `block_id` page prefix == `page_number`, and every quote is
   present in that page's text; the multipage fixture yields evidence on pages
   `[1,2,3,4,5]`
5. missing criteria are genuinely absent: `missing` ⇒ zero supporting items;
   `weak` ⇒ every supporting item fails the strength/confidence gate
6. contradictions: every `contradictory_evidence` ID resolves to an item with
   polarity `contradicts` (and none appears where the envelope forbids them)
7. repeated header (`MERIDIAN AEROSPACE…`, 5×) and per-page page-number lines
   stripped (metadata counters ≥ 5 each)

## 12. Remaining limitations

1. **Not a benchmark**: 15 synthetic-realistic documents; no precision/recall
   or scientific-accuracy claim; corpus vocabulary deliberately overlaps
   criteria hints (as real TRA-style documents do) — domain-shifted prose may
   behave differently.
2. The per-section candidate cap is still positional beyond 200
   sentences/section; only the observed failure mode was eliminated.
3. Gap view covers next-level blockers + lower-level weak/contradicted
   criteria; contradictions on levels *above* the prediction surface only in
   `contradictory_evidence`, not in `next_trl_gaps` (by M2 design; observed on
   `adv_negated`).
4. Criteria with `min_strength: strong` whose declared `evidence_types` map to
   moderate strength are satisfiable only when `type_cues` latch a strong type
   (`test`/`demonstration`/`operation`) from the wording — worked for all
   corpus documents, but the config tension (`evidence_types` is advisory, not
   gating) remains.
5. `weak` next-level status is exercised in unit tests but not end-to-end in
   this corpus.
6. Confidence bands are rule-calibrated, not statistically calibrated.
7. English-only cues; performance figures are machine-specific.
